# SafeOCR: anonymizing identity documents (OCR + black boxes)

Project #03. The user points to an image of an ID card. The system recognizes the text (OCR), finds the
personal data (CNP, name, address, ID series/number, MRZ) and produces a new image with black
rectangles over it. **Only fictive documents** are used, generated by `scripts/generate_samples.py`.

**Privacy by design:** the model (agent) never sees the raw text of the document. The MCP tools work
with identifiers and return only reports (data types, counts, positions, pass/fail). The text
and the values stay in the local store `data/store/`.

```
web/ (Next.js) ──HTTP──▶ FastAPI (server/safeocr/api) ──MCP client (in-memory)──▶ FastMCP server
                                                                                  │
                                    ocr_document → detect_pii → redact_image → verify_redaction → announce
                                                                                  │
                                                                        data/store/ (local only)
```

## Structure

```
fastmcp.json              MCP server config (FastMCP)
config/settings.yaml      app config (OCR backend, paths, PII types, future LLM/TTS)
requirements.txt          Python dependencies (+ `-e .` for the safeocr package)
server/mcp_app.py         entrypoint for `fastmcp run fastmcp.json`
server/safeocr/
  mcp_server.py           the 5 MCP tools
  service.py              pipeline logic (returns reports only)
  ocr/                    stub (ground truth + pixel check) | tesseract
  pii/                    cnp.py (regex + control digit), rules.py, detector.py
  redact.py, evaluation.py (recall), storage.py, config.py
  llm/                    local SLM hook (placeholder)
  tts/                    local TTS hook (placeholder) + Romanian announcement text
  agent/                  chat agent: Ollama client + MCP tools (chat.py, ollama.py)
  api/main.py             FastAPI (+ /api/chat streaming)
scripts/generate_samples.py   12 fictive documents (rotation, noise, blur, 5 fonts) + *.gt.json
scripts/evaluate_recall.py    recall report (covered / existing)
tests/                    pytest
web/                      Next.js 16: / = chat, /pipeline = step-by-step page
```

## Setup

```bash
# Python >= 3.10 (3.12 recommended)
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

python scripts/generate_samples.py      # -> data/samples/doc_00..11.png + .gt.json
python scripts/evaluate_recall.py       # recall per type + verification
pytest
```

## Running

```bash
# 1) API (port 8000)
uvicorn safeocr.api.main:app --reload --app-dir server

# 2) Frontend (port 3000)
cd web && cp .env.example .env.local && npm install && npm run dev
```

- http://localhost:3000: **Chat** (ChatGPT-style). Attach a card with the paperclip, drag & drop or paste, and ask questions.
- http://localhost:3000/pipeline: the original step-by-step page.

### Chat (local model via Ollama)

```bash
ollama pull qwen3:1.7b      # model set in config/settings.yaml -> llm.model
ollama serve                # if not already running
```

`POST /api/chat` streams NDJSON events (`tool_call`, `tool_result`, `recall`, `token`, `done`).
How it works ([server/safeocr/agent/chat.py](server/safeocr/agent/chat.py)):

- **Attached image:** the backend runs the 5 MCP tools deterministically. The calls show up in the chat and
  only their *reports* go into the model's context. The model then summarizes them.
- **Follow-ups** ("now cover only the CNP"): the model calls the MCP tools itself. A small model sometimes invents
  ids, so the backend replaces them with the real ones from the conversation. A type name (`"CNP"`) is mapped to
  the detection ids of that type.
- The language of the answer follows the user's message (Romanian/English).
- With OCR `stub`, an upload works only if it is byte-identical to a generated sample (e.g. dragged from
  `data/samples/`). Real photos need Tesseract.

### Standalone MCP server

```bash
fastmcp run fastmcp.json      # stdio
fastmcp dev fastmcp.json      # MCP Inspector (UI)
fastmcp inspect fastmcp.json  # list the tools
```

For an external MCP client (e.g. Claude Desktop/Code), the config looks like this:

```json
{
  "mcpServers": {
    "safeocr": {
      "command": "/abs/path/safeocr/.venv/bin/fastmcp",
      "args": ["run", "/abs/path/safeocr/fastmcp.json"]
    }
  }
}
```

## MCP tools

| Tool | Returns (never the values) |
|---|---|
| `ocr_document(path)` | `document_id`, word/line counts |
| `detect_pii(document_id)` | `detection_set_id`, counts per type, `[{id, type, bbox}]` |
| `redact_image(document_id, detection_ids?)` | `result_id`, boxes drawn per type |
| `verify_redaction(result_id)` | `passed`, `remaining_counts` |
| `announce(result_id)` | announcement text in Romanian (TTS later) |

`ocr_document` only accepts images from `paths.allowed_input_dirs` (default `data/samples`, `data/uploads`).

## OCR: stub vs Tesseract

Tesseract is not installed yet, so the default backend is `stub`. It reads the ground truth of the generated
samples but **checks the pixels**: a word covered at least 85% by black counts as unreadable. Verification is
therefore real: if a box is missing, the data is detected again.

To use real OCR:

```bash
brew install tesseract tesseract-lang   # includes `ron`
export SAFEOCR_OCR__BACKEND=tesseract   # or ocr.backend: tesseract in config/settings.yaml
```

The rules (`pii/rules.py`) were tuned on the generated layout. With Tesseract, run
`scripts/evaluate_recall.py` again and adjust them.
